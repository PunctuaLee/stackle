# Stackle

Tap to drop. Stack it perfect. A one-thumb tower-stacking game for iOS, Android and the web.

- `stackle.html` is the whole game: one file, no dependencies. Edit this.
- `scripts/build.sh` wraps it into `www/index.html`, the page the phones load (adds the viewport, PWA manifest, icons, offline cache).
- `ios/` and `android/` are the native shells, generated by Capacitor 8 (iOS uses Swift Package Manager, so no CocoaPods needed). `www/` is copied into them on every `npm run sync`.
- `assets/` holds the icon and splash sources. `npm run icons` regenerates every platform size from them.

## Daily workflow

```sh
npm run build        # rebuild www/ from stackle.html
npm run serve        # play it in a desktop browser at http://localhost:3000
npm run ios          # rebuild, sync, open Xcode
npm run android      # rebuild, sync, open Android Studio
```

## One-time setup

1. **Node** is installed with Homebrew (`brew install node`). Then in this folder: `npm install`.
2. **iOS**: install Xcode from the Mac App Store (free, about 15 GB), open it once to accept the licence, then run
   `sudo xcode-select -s /Applications/Xcode.app` and `npm run ios`. In Xcode pick your team under
   Signing & Capabilities, choose a simulator or your iPhone, press Run. Publishing needs an Apple Developer account (USD 99/year).
3. **Android**: install Android Studio (`brew install --cask android-studio`), let it download the SDK, then `npm run android`.
   Press Run on an emulator or a phone with USB debugging on. Publishing needs a Google Play developer account (USD 25 once).
4. **Web / PWA**: upload the contents of `www/` to any static host (Netlify, Cloudflare Pages, GitHub Pages). It installs to the home screen and works offline.

## Web version and database (feedback phase)

The web build deploys itself: every push to `main` on GitHub runs `.github/workflows/pages.yml`, which builds `www/`
and publishes it to GitHub Pages. The public link is `https://<your-github-user>.github.io/stackle/`.

The leaderboard and the feedback box talk to a free Supabase project. Until it is configured they stay hidden, so the game
works without it. To switch them on:

1. Create a free project at supabase.com (the free tier is plenty for thousands of players).
2. Open **SQL Editor**, paste the whole of `supabase/schema.sql`, press **Run**.
3. Open **Project Settings → API**. Copy the **Project URL** and the **anon public** key into `config.json`.
4. `npm run build`, commit, push. The anon key is meant to be public; the SQL policies decide what it may do
   (post scores, read scores, post feedback, never read feedback).

Reading what players send: Supabase **Table Editor → feedback**. Daily rankings: **Table Editor → scores**, or the
queries at the bottom of `schema.sql`. Scores are posted from the browser, so a determined cheater can post a fake one.
That is fine for a feedback phase; a server-side check comes later if the leaderboard becomes a real feature.

## Release checklist

- Bump `version` in `package.json`, plus the build number in Xcode and `versionCode` in `android/app/build.gradle`.
- Bump `CACHE` in `assets/sw.js` so web players get the new version.
- Screenshots: 6.7" iPhone and 6.5" iPhone for App Store, a phone set for Play Store. The game-over screen with a big score makes the best one.
- Store listing: the one-liner is already the tagline. "Tap to drop. Stack it perfect."
